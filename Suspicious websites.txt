! ── RULE CONVENTION (single source of truth for all entries below) ─────────────────────
! Every rule in this list uses the same fixed pattern:
!   ||<domain>^$script,subdocument,websocket,third-party
! i.e. block only script/iframe loads from third-party requests to the domain, never the
! domain's own first-party navigation. This keeps false-positive risk very low. If this
! convention ever needs to change, change it in this comment and re-generate the rules —
! do not hand-edit individual modifier strings.
!
! ── EXCLUDED ON PURPOSE ──────────────────────────────────────────────────────────────
! The following domains are deliberately NOT in this list even though they can host
! attacker content, because they are also widely used as legitimate third-party
! embeds/CDNs/backends, so blocking script/subdocument loads from them has a real chance
! of breaking normal, non-malicious sites:
!   sites.google.com        - embedded Google Forms/Docs/Sheets/Maps on many sites
!   firebaseapp.com         - Firebase-hosted widgets/chat/auth embedded elsewhere
!   herokuapp.com           - small SaaS backends called via script from client sites
!   workers.dev             - Cloudflare Workers used as third-party backend APIs
!   blob.core.windows.net   - Azure Blob Storage serving embedded images/video/assets
!   web.core.windows.net    - Azure static-website storage serving embedded assets
!   backblazeb2.com         - object storage CDN for embedded media
!   r2.dev                  - Cloudflare R2 object storage CDN for embedded media
! If you want maximum coverage over minimum breakage risk, you can add these back
! yourself, ideally scoped to the specific abused subdomain rather than the whole domain.
!
